**Native end-to-end verification passed for three fresh synthetic scenarios.**
The measured total is **15 spans, 13 events, and 26 required metric series**.
The workbook's saved definition, LAW source/gallery association, seven live
panel queries, and two selected drilldowns are also verified.
**Authenticated portal rendering is not verified.** All 233 integrated tests
and the live read-only teardown prechecks passed. Independent release review

These are measured results from the fresh v1 rebuild on
**2026-09-13**, not results carried over from another deployment. All three runs
returned `status: passed` and `azure_ingestion_proven: true` from the native
verifier querying the real LAW and AMW. The run UUID mapping, manifests,
resource identifiers, raw queries, and diagnostic output remain
private under `.local/`. Access tokens are acquired at runtime and are not
persisted in the run evidence.

## Reproduce and interpret

Follow [deployment](../deployment.md) and [verification](../verification.md)
for exact commands. Each smoke invocation produces a new UUID; verify that
completed run with:

```bash
python3 -m scripts.verify_native --run-id "$RUN_ID" --timeout-seconds 600
```

Require complete native spans/events/resource correlation and the required AMW
histogram series. A successful deployment, zero CLI exit, HTTP response alone,
or metrics-only result cannot replace those checks.

Fresh DCE/DCR deployments can return HTTP 503 before the data plane is ready.
After propagation, obtain a new bounded synthetic run and its own backend
result. An authenticated empty protobuf request returning HTTP 400 is not
readiness proof. The anonymous HTTP 401 demonstrates the authentication
boundary, not successful ingestion of a valid complete payload.

## Proof boundaries

- Client-generated telemetry and backend correlation do not establish
  trustworthy user attribution, cryptographic producer attestation, or complete
  tamper-proof cybersecurity auditing.
- Required-signal persistence does not establish lossless export of every CLI
  record or feature.
- Metadata-only validation checks returned attributes, not absence from CLI
  memory or traffic before ingestion.
- Histogram count/sum proof does not establish bucket-by-bucket fidelity or
  support for SDK temporality/aggregation environment-variable overrides.
- Token and latency workbook panels use span attributes, not the AMW histogram
  datasource.
- Normal-session onboarding is documented but not executed; all scenario proof
  is synthetic.
- Azure native OTLP remains preview, without an SLA and not recommended for
  production. Example v1 does not mean service GA.

Only sanitized findings are recorded here. Raw evidence stays private, the
repository remains private, and the [LinkedIn draft](../linkedin.md) has not
been posted.
